# S44a: the usage report works on a real install

Base: `a737ae9d` (0.8.68 batch). Plan step S44a in PLAN-0.4.0-v2.md. Tests: `packages/codex-agents/tests/test_s44a_usage_install.py`.

Found on the owner's installed 0.8.67: `learning-usage-report --project-root . --since .. --until ..` refused
`usage_state_unavailable` while `learning-status` was ready, and learning-status showed
`ingestion.coverage.root_usage: false`.

## Root causes (reproduced on a throwaway installed copy; no live state was read)

1. **The refusal was the project root, not the state.** `usage_report` took `.` as "project root must be absolute"
   and mapped that StateError, with every state and key failure, to one code `usage_state_unavailable`. `learning-status`
   resolves the root first (an installed CLI replaces it with its own bundle root). With the absolute path the same
   install and state report fine. The key file, state root mode and ownership checks (`CollectorPaths.digest_key`) are
   the same for both commands and are unchanged.
2. **`root_usage: false` is not a missing ingestion.** It is the Codex hook surface's capability flag
   (`config/learning-clients.json`, checked by `validation.py` and by the candidate-promotion client-coverage gate):
   hooks carry no token counts. It never described the runs. Each bridged child's tokens are already read from the
   child's own output (Claude `result` frame, Codex `turn.completed` frame), recorded as `provider_usage` and listed by
   the report. The flags stay false (flipping them would claim hook usage coverage that does not exist and would open the
   promotion gate); the report and learning-status now say this and show per-provider run usage.
3. A window with no data was an empty list with no explanation.
