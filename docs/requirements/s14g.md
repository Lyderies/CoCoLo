The account hold table is **run_holds**; there is no separate `account_holds` SQL table. The only runtime hold tables with this composite key are run_holds and project_holds. Account readers already name their applicable kinds at this base (some predicates are on later continuation lines). Neither lost-run settlement nor original-open cleanup needs a narrower kind filter. Both lineage queries already retain `IN ('run_slot','binding')` after S14e/S14f.

## Writer-derived kinds and semantics

| Register | Writer and identity |
| --- | --- |
| run_holds.run_slot | `run_holds_schema.py` source triggers/adoption: `active_run_capacity.handle_digest`. |
| run_holds.binding | Same module: `host_run_bindings.handle_digest`. Both handle kinds remain in custody/lost-run queries. |
| run_holds.probe | Same module: `account_billing_probe_requests.request_key`; never substitute it for a launch-handle kind. |
| project_holds | `project_holds_schema.HOLD_KINDS`, `take_hold` and adopters: driver_entry/preparation/lease/open_binding/result_custody use attempt identity, reservation uses claim id, orchestration uses its handle. Memory/register readers retain their complete existing kind lists. |
| takeover adoption | `_settlement_input` and `adopt_project` only process lease/reservation; the old loop explicitly skipped all other kinds. Moving that filter into SQL preserves behavior. `state<>'released'` is implied by `state='releasing'` and exposes the existing partial index. |

## Fixture and method

The table below is the source-derived SQL inventory compiled by the real SQLite schemas opened by `LearningStoreTests` (two registered projects) and `ResultLeaseTests` (two product-written lease/custody pairs), SQLite **3.53.4**. No simplified schema is used for these plan tests. Reused identical SQL is grouped with all discovered source lines; shared fragments and complete embeddings both appear where applicable. Generic snapshot/size/source-image reads are captured from their runtime producers. SQL parameters use small representative values; row-page and owner-window variants are included. Full EQP output, including non-hold source steps, is in [s14g/plans.json](s14g/plans.json).

Every recorded full-key access is pinned by `test_S14G_2_real_schema_inventory`; new/changed SQL requires the inventory to be reviewed. Standalone point tests additionally pin each optimized lookup. Evidence-validation scans must cover all retained kinds, including released evidence. State/identity range reads without a complete point identity cannot be turned into point lookups by adding a kind alone.

No load/timing benchmark was needed. An attempted measurement-runner preflight was refused because this workspace sandbox denies `ps`; it ran no measurement child. EQP inspection is performed as ordinary registered SQLite plan tests.
