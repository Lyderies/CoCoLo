# S11 - HM-2a: leftover CoCoLo preparation folders (Unit 3.9, health monitor)

Authority: plan step S11 (HM-2, SW-8), owner decision 309 (preparation cleanup stays with the
driver), E1b-1 and decision 311 (ledger and history access goes through the owner thread).
Base: `ce81bd96` (0.8.67). VERSION and the digest catalogue stay unchanged.

New module `codex_agents/health_workspaces.py`: one health check, `workspaces`. It reads the
preparation folders in CoCoLo's scratch area and the records of who owns them. It never edits
`codex_preparation.py` state and never opens the ledger or history itself. Where it learns what is
owed to a driver (decision 309's pending removals) it is given a reader by its caller, and that
reader goes through the owner thread (HM2A-9).

A folder is "ours" only if it is `prepare-*`, directly in the real scratch container, a real folder
of this user (the same test as `codex_preparation.remove_recorded_workspace`, decision 309).

Fix round (review r1, primary decision): deleting a folder needs POSITIVE proof that its owner is gone.
Missing records plus age are not proof; when in doubt (truncated records, unreadable state, unknown owner)
nothing is deleted and it is reported. The proof is an owner marker, `cocolo-owner.json`, that the
preparation lane now writes into each new folder (runtime change in `codex_preparation.py`, format in
`host_paths.preparation_owner_marker`, wired by `project_driver.RunDriver` with its launch-journal
instance): it names the learning state root, the project and the journal instance, and the folder is
removable only while that instance's `<instance>.lock` is free (a non-blocking flock succeeds,
`launch_journal.instance_stopped`). Folders made before this change have no marker and are only reported.

Limits stated plainly:

- The check is inert until it is given its two readers. Registration in the collector (with the
  readers; the pending reader goes through the owner thread) is done by the primary after S5
  (`learning_store.py` is not edited here). `health_workspaces.register(monitor, state_root, pending=...)` is the one call.
  `health_monitor.py` is deliberately unchanged: adding the check to `with_builtin_checks` would put an inert
  check in front of three existing name-list assertions and double-register once the wired one is added.
- A launch-journal entry that cannot be read means the live set is not known, so nothing is removed
  until it is fixed (HM2A-7); the owner is told each pass.
- A folder a driver creates and has not recorded yet is protected by its owner's held journal lock (its
  marker names it); before the marker is written it has no marker and is only reported, never removed.
  `MIN_ORPHAN_AGE_SECONDS` is an extra guard on the marker's age, never proof by itself.
- Folders without a marker (made before this change, or whose marker could not be written), folders of
  another state root, and folders whose instance lock file is gone (a normal release removes it) are only
  reported (`owner_unknown`); a person removes them. `remove_recorded_workspace` (decision 309) is unchanged.
- A level of ours made unlistable (no read bit) gets its mode back only through a verified O_SEARCH descriptor;
  where the platform has no O_SEARCH, or the level has no search bit either (mode 000), it is left and the folder
  reported as not removed. Before owner proof such a top folder is looked into only through O_SEARCH, or not at all
  (owner not proven, reported).
- Write workspaces are part b (S21), not here.
