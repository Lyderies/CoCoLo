# S14d: enforced measurement budgets (decision 371)

Authority: OWNER-DECISIONS-0.4.0.md decision 371; BUILDER-RULES-0.4.0.md "Measurement, load and synthetic-data work".
A recurring breach of the test budgets (S14c built 12 GB over 2 h) means the budget is enforced by code, not by a rule.

| Requirement | Acceptance |
| --- | --- |
| S14D-1 | `scripts/run_measurement.py` runs one measurement script as a child in its own process group with enforced caps: wall clock (default 300 s; a script may declare its own; hard maximum 900 s unless `--approve-decision N` names a decision number), generated-data bytes under a dedicated output directory it creates (default 1 GiB, polled about every 0.2 s), and peak RSS summed over the group (default 3 GiB). On a breach it kills only the process group it started, deletes the data, prints one plain line (limit, measured value, how to change it) and exits 3. |
| S14D-2 | The generated-data directory is always deleted at the end, on success or failure, unless `--keep` is given; the runner reports the bytes written. |
| S14D-3 | Every `measure_*.py` in `scripts/` and `packages/*/scripts/` declares `MEASUREMENT_BUDGET = {...}` (keys `wall_seconds`, `data_mib`, `rss_mib`, optional `decision`) as a literal; a registry test fails if one is missing, malformed, or over the 900 s hard maximum without a decision number. The runner reads it without importing the script. |
| S14D-4 | A test fails if any file in `docs/`, `scripts/` or `packages/*/scripts/` invokes a `measure_*.py` directly (python or `$PY` followed by the script) instead of through `scripts/run_measurement.py`. Only the runner's own tests are exempt. |
| S14D-5 | Nothing does I/O at import; the runner tests use tiny fake measure scripts (sleep, allocate, write a few MiB) with low caps so each cap trips within seconds. |

Budgets for the existing scripts are estimates from each script's declared sizes; none was run for this step. Tighten them
from the first measured run through the runner. `measure_test_behaviour.py` runs whole suites and cannot fit the 300 s
default: it declares the 900 s hard maximum and should be run with `--suite` for one suite at a time.
