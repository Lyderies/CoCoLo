# S14d: enforced measurement budgets (decision 371)

Authority: OWNER-DECISIONS-0.4.0.md decision 371; BUILDER-RULES-0.4.0.md "Measurement, load and synthetic-data work".
A recurring breach of the test budgets (S14c built 12 GB over 2 h) means the budget is enforced by code, not by a rule.

| Requirement | Acceptance |
| --- | --- |
| S14D-1 | `scripts/run_measurement.py` runs one measurement script as a child in its own process group with enforced caps: wall clock (default 300 s; a script may declare its own; hard maximum 900 s unless `--approve-decision N` names a decision number), generated-data bytes under a dedicated output directory it creates (default 1 GiB, polled about every 0.2 s), and peak RSS summed over the group (default 3 GiB). On a breach it kills only the process group it started, deletes the data, prints one plain line (limit, measured value, how to change it) and exits 3. |
| S14D-2 | The generated-data directory is always deleted at the end, on success or failure, unless `--keep` is given; the runner reports the bytes written. |
| S14D-3 | Every `measure_*.py` in `scripts/` and `packages/*/scripts/` declares `MEASUREMENT_BUDGET = {...}` (keys `wall_seconds`, `data_mib`, `rss_mib`, optional `decision`) as a literal; a registry test fails if one is missing, malformed, or over the 900 s hard maximum without a decision number. The runner reads it without importing the script. |
| S14D-4 | A test fails if any file in `docs/`, `scripts/` or `packages/*/scripts/` invokes a `measure_*.py` directly (python or `$PY` followed by the script) instead of through `scripts/run_measurement.py`. Only the runner's own tests are exempt. |
| S14D-5 | Nothing does I/O at import; the runner tests use tiny fake measure scripts (sleep, allocate, write a few MiB) with low caps so each cap trips within seconds. |

Budgets for the existing scripts are estimates from each script's declared sizes; none was run for this step. Tighten them
from the first measured run through the runner. `measure_test_behaviour.py` runs whole suites and cannot fit the 300 s
default: it declares the 900 s hard maximum and should be run with `--suite` for one suite at a time.

## Review round r1 (Codex NOT-READY)

- Hard maxima are 900 s, 4 GiB data and 6 GiB memory; only the caller's `--approve-decision N` goes over them. A `decision` key in a script's `MEASUREMENT_BUDGET` is accepted but never honoured, and declared values must be positive whole numbers within the maxima. Non-finite or negative numbers are refused.
- Descendants: every poll walks parent pids from the child (so `setsid()` grandchildren are found) and the process group; leftovers are killed when the child exits or on a breach, by pid from that tree only.
- Volume guard: free space of the data dir's volume and of `/tmp`'s is recorded at start; a drop over the data cap plus 16 MiB is a breach. Data written outside the data dir is detected but not deleted. NOT covered: data written to another volume, and free-space noise from other writers (hence the slack).
- After exit the runner re-checks peak memory (`getrusage`) and recounts bytes; a final over-cap is a breach. A `ps` failure is an error (exit 4), never zero memory.
- Launch and deletion failures are reported (exit 4); unreadable subdirectories are made writable before deletion. Each poll bounds its directory walk (0.5 s) and `ps` (3 s), and checks the wall clock first.
- `measure_test_behaviour.py` writes under `MEASUREMENT_OUTPUT_DIR`; a test fails if any measure script names `/tmp`.
- The S14D-4 scanner catches `-m`, `./script`, argument lists and `subprocess` calls; only a real runner invocation is exempt; Markdown prose counts only inside code.

## Not covered (by design), decision 373

Threat model: accidental overruns by our own measurement scripts (S14c built 12 GB over 2 h), not a deliberately evasive script. Not chased further:

- Another volume: data written to a different volume than the data dir's or /tmp's is neither counted nor deleted.
- Data written outside the data dir is only detected (volume free-space drop), never deleted.
- Descendants reparented (parent exited) before a poll, and children of a detached survivor, can escape the process-tree walk.
- A file written and deleted between two polls, and an aggregate memory peak that exists only between polls (the post-exit `getrusage` check sees only the largest single process), can be missed.
- Free-space noise from other writers on the same volume (hence the 16 MiB slack).
