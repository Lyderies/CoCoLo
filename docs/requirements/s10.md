# S10: HM-6 disk and memory

Sources: plan v2 step S10 and SW HM-6; supervisor slices HM-6; owner decisions 340
(refuse new runs below 2 GiB or 5% free, whichever is larger; raise it to the user; easy to
configure) and 341 (limits configurable). VM-disk rows are added in S19, not here.

Test methods are in `tests/test_health_resources.py`. Mapping: `tests/requirements/s10.json`
and `scripts/test-requirements.json`.

| ID | Observable requirement |
|---|---|
| S10-HM6-1 | A new run is refused when free space on the workspace root is below the larger of 2 GiB and 5% of that disk. Just below refuses; equal and above allow. Checked separately from the state folder. |
| S10-HM6-2 | The same rule applies to the state folder, separately from the workspace root. A low folder is named; a healthy one is not. |
| S10-HM6-3 | The needed amount is the larger of `disk_free_bytes` and `disk_free_percent` of the disk: 2 GiB on small disks, 5% on large ones; the switch-over is exact. |
| S10-HM6-4 | A refused run gives a plain reason: no traceback or code names, the folder, the free and needed amounts, and how to change the limit. The refusal happens in `RunDriver._resource_preflight`, called from the run.register answer path before `_register`, so before any run state, journal entry or registration exists. A retry of an already registered run is not re-checked. |
| S10-HM6-5 | Limits come from the one shared user-settings file (`user_settings.load`). Changed values take effect on the next check. Out-of-range values (disk percent outside 1-99, byte limits below 1 MiB, memory percent outside 1-99) make the whole file invalid: defaults stay in force with the plain warning. |
| S10-HM6-6 | Memory pressure (available memory below `memory_available_percent`, default 10) is reported to status as a plain machine finding and never refuses a run. An unknown memory reading reports nothing. |
| S10-HM6-7 | A disk probe that fails or returns nonsense fails safe: new runs are refused with a plain reason naming the folder and saying the free space could not be read (a run that might fill the disk is worse than a short pause). The health check reports it. |
| S10-HM6-8 | Low disk is also raised to the user: the health check reports a plain finding per low or unreadable folder, which reaches the status warning list. Healthy disks report nothing. No I/O happens at import; probes are injectable. |

## Decisions recorded here
- Probe failure refuses (fail safe), because the owner's intent is to protect the disk; the reply to the
  caller keeps the existing `history_service_unavailable` code (no new wire code); the plain text is the
  exception message and the health finding.
- New settings key `memory_available_percent` (default 10, range 1-99): decision 340/341 give no memory value.
- Wiring `health_resources.register(monitor, ...)` is a function, like S8/S9; primary wiring stays deferred.
