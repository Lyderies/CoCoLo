**E1-1 — Consent first.** RS-11, decision 90.11 A. Setup asks once, in plain words with the real reason, with a pick-list (yes / not now) and a details view, before the collector gets a login-start entry. Nothing is written or run without a yes; not now writes and runs nothing; a failed install is reported and not remembered. **E1-2 — macOS entry.** A launchd user agent in the account's LaunchAgents folder runs the installed collector command (absolute paths, isolated Python, learning-serve) at login, restarts it after a crash with a throttle (KeepAlive on failure, ThrottleInterval), logs to the CoCoLo log folder, and holds no secret. Loaded through an injected runner (launchctl bootstrap), never the real one in tests. Test: tests.test_login_start.InstallTests.test_E1_2_launchd_plist_and_load.

**E1-3 — Linux entry.** A systemd user unit runs the same command, with Restart=on-failure, RestartSec and StartLimit back-off, logs to the CoCoLo log folder, WantedBy=default.target, and no secret; enabled through the injected runner (systemctl --user). Test: tests.test_login_start.InstallTests.test_E1_3_systemd_unit_and_enable.

**E1-4 — Ask once.** The answer (yes or no) is kept in the private installer folder beside the project list. A re-run of setup does not ask again; with no private place to keep the answer, setup does not ask and says so; an update never asks. **E1-6 — Refusals.** A relative command path, a symlinked entry path, an existing entry that is another user's or that others can change, or an unsupported system is refused with a plain reason and changes nothing; the entry is written through folder descriptors opened without following a link. **E1-8 — Status reports the entry.** Setup's status lines report the login entry as on, off or stale. Stale means the entry's command no longer matches the installed collector's path, or the installed runtime's identity (the digest the owner authorized) is not the one the entry was last written for, or that identity cannot be read. The entry is read only through folder descriptors opened without following a link, never blocking on a FIFO or device, and only when it is the owner's and others cannot change it; otherwise it is stale. A status line holds no private value: no digest, key or folder path; its reason is one of a fixed set. Tests: tests.test_login_start.StatusTests.test_E1_8_status_is_on_off_or_stale_and_names_no_private_value, tests.test_login_start.StatusTests.test_E1_8_the_runtime_identity_is_read_only_from_a_private_plain_authorization_file, tests.test_login_start.ReviewFixTests.test_E1_8_status_never_follows_a_link_or_blocks_on_a_special_file_or_reads_another_users_entry.

**E1-9 — An update keeps the entry current.** When consent is already recorded (E1-4: an update never asks), an update that changes the collector's path or the authorized runtime digest rewrites the existing entry through the runner and records what it was written for; when it cannot, the entry is reported stale with a plain reason and the earlier entry is kept. The authorized runtime is the one the collector's own active-identity check (require_authorized_collector_runtime: exact schema, not quiesced, owner-only, never through a link) accepts for this setup's attested runtime; any other is reported stale and nothing is written. An update never asks and never creates an entry, whatever its answers file says. The record and the answer are read only from owner-only plain files of the owner's, never through a link or blocking. A failure shows a fixed reason with no path; when the record cannot be kept the earlier entry is put back and the entry is not shown as refreshed. An entry that is current is not rewritten; with no recorded yes, or with no entry, nothing is written. Tests: tests.test_login_start.InstallTests.test_E1_9_a_failed_refresh_puts_a_stopped_systemd_unit_back_stopped_and_not_enabled, tests.test_login_start.InstallTests.test_E1_9_a_refresh_does_not_recreate_an_entry_that_vanished, tests.test_login_start.ReviewFixTests.test_E1_9_a_rewrite_needs_the_collectors_active_identity_for_the_attested_runtime, tests.test_login_start.ReviewFixTests.test_E1_9_the_runtime_record_and_the_answer_are_read_only_from_private_plain_files_of_this_user, tests.test_login_start.ReviewFixTests.test_E1_9_an_update_never_creates_an_entry_from_an_answers_file, tests.test_login_start.ReviewFixTests.test_E1_9_a_failed_rewrite_shows_a_fixed_reason_with_no_path, tests.test_login_start.ReviewFixTests.test_E1_9_a_failed_record_write_keeps_the_earlier_entry_and_is_not_shown_as_refreshed, tests.test_login_start.UpgradeTests.test_E1_9_an_update_that_moves_the_collector_rewrites_the_entry_without_asking, tests.test_login_start.UpgradeTests.test_E1_9_an_update_that_changes_the_runtime_digest_rewrites_the_entry, tests.test_login_start.UpgradeTests.test_E1_9_an_entry_that_cannot_be_rewritten_is_reported_stale_with_a_reason, tests.test_login_start.UpgradeTests.test_E1_9_a_current_entry_a_missing_entry_and_no_consent_write_nothing.

**E1-10 — The entry's command passes the runtime check.** The command the rendered entry holds (launchd ProgramArguments, systemd ExecStart), run as given, reaches require_authorized_collector_runtime and starts only when the state's authorized runtime is the installed one; with a different authorized digest it is refused with runtime_unauthorized. The CLI prints the refusal's message, not its code, so the run's printed refusal is matched to the message the collector's own check raises with that code. Tests: tests.test_login_start.CommandAuthorizationTests.test_E1_10_the_rendered_command_passes_require_authorized_collector_runtime, tests.test_login_start.CommandAuthorizationTests.test_E1_10_the_installed_command_run_as_given_is_refused_with_runtime_unauthorized (the rendered launchd command run as a real process against a temporary installed copy). The real launchd and systemd back-off on a real install stays an owner check.
