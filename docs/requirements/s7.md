## Lifecycle flow L16 (tests/e2e/requirements.json, scripts/e2e_checks_owner_load.py)

Run with `scripts/e2e_lifecycle.py --flows L16`. Two projects share one collector. The installed hook delivers events (a
large project's backlog and a small project's few events), the installed CLI makes account calls
(`provider-observe` with a request id, each id sent twice) and reads status, and a prober process asks the installed
client library for health throughout. A barrier releases every caller together; waits are for process or thread ends and
for the prober's `ready` line.

| ID | Check | What it reads, through which path |
| --- | --- | --- |
| L16.1 | `l16_1_hooks_and_account_calls_at_once_lose_and_duplicate_nothing` | event rows per project (read-only ledger) against events sent; the collector's own accepted count (`learning-status`); recorded observation requests against unique request ids; the status refusal counters empty. |
| L16.2 | `l16_2_small_project_gets_its_turns_while_the_large_projects_backlog_drains` | the projects of the event rows in write order (`rowid`; `source_sequence` counts per project). |
| L16.3 | `l16_3_health_stays_responsive_and_the_collector_is_not_restarted` | the prober's answered counts and slowest answer; the collector's pid before and after; status ready and no previous exit. |

Test-only faults (`--fault NAME`, chosen only by the runner): `ingest_lost` (L16.1 red), `health_stalls` (L16.3 red).
`tests/test_e2e_owner_load.py` proves each judge goes red on the failure it names.

L16.2 limit, stated plainly: through real processes the owner never holds a backlog deep enough to show a queue that
ignores project turns (a `fifo_turns` fault left L16.2 green), so L16.2 only guards against starvation of the small
project. Fair turns themselves are proven deterministically in `OwnerLoadTests` (a held owner, a real backlog of
ingests), which goes red when the queue serves one project until its backlog is empty.

## Bounds used

- First response: 1.0 s (the requirement). Measured warm-cache on a 310 MB ledger: 9 to 12 ms (ANALYSIS-0.4.0-e0b-v2).
- Health during the load: 2000 ms. The owner's own queue wait is 800 ms; health does not wait for the owner.
- Load sizes are counts, inside the queue's limits (12 requests, 6 per project): the e2e load never needs a refusal.
